## [v1.10.8] - 2026-08-28 - ☀️ - UPDATE - More Accurate Solar Shadows: Fixing Distortion for Concave Buildings and Trees
1. **Shadows of concave buildings are no longer filled in solid**: previously, the building outline and its projected roof were merged and reduced to a "convex hull", so L-shaped terraced houses and courtyard apartment blocks (with an internal light well) had their concave sections incorrectly filled in. The algorithm now sweeps a shadow band along each edge instead, preserving light wells and concave corners. Verified against an L-shaped building: the old algorithm filled in the concave corner; the new one does not.
2. **Tree shadows are no longer too thick**: tree canopies sit several metres above the ground, but the shadow calculation previously included the ground-level outline as well, making tree shadows look like a thick tube dragging out from the base of the trunk. The calculation now projects only the canopy itself, so tree shadows return to their natural, clustered shape.
3. **More stable loading of building footprint data**: map panning now delays the query by 0.5 seconds (to avoid bombarding the data server with repeated requests while dragging); results for the same viewport are reused rather than re-queried; a failed query is automatically retried once; and data is re-fetched after zooming back into the supported range or resizing the window, so the layer no longer gets stuck blank.
4. **Added loading-state indicators**: footprint queries take several seconds, during which the screen previously gave no feedback at all. It now displays "Loading building outlines…", with corresponding messages while retrying, on failure, and when the map needs to be zoomed in further.
5. **Documented the data source for building heights**: shadow length depends on building height, and not every building in OpenStreetMap has this attribute tagged. The layer description now notes that untagged buildings are estimated at 12 metres (roughly 4 storeys), so shadow length is indicative only.

## [v1.10.7] - 2026-08-28 - 🧹 - UPDATE - Remove the Unused Puppeteer Dependency and Clean Up Stale Debug Files
1. **Removed `puppeteer`**: this package served only a one-off debugging script from May 2026 and was never used by the site itself, yet it alone accounted for all 8 high-risk findings in the security audit. After removal, high-risk findings dropped from 8 to 2 (both indirect dependencies of the ESLint toolchain, with no effect on the site at runtime); the dependency count fell by 78 packages, install size shrank by roughly 49 MB, and deployment builds are correspondingly faster.
2. **Cleaned up stale debug files**: deleted `test_crash.js`, `test_crash2.js`, and `test-cluster.js`. Before removal, we re-verified that the layer-crash issue these scripts were written to investigate no longer occurs — with both the "Street Tree Shade" and "Pavement Extent" layers enabled at once (roughly 6 MB of data combined), the page showed no errors, memory usage stayed at 22 MB, and the map functioned normally.
3. **Removed two further unused dependencies**: `react-leaflet-cluster` (not referenced anywhere in the codebase) and `leaflet-shadow-simulator` (the solar shadow layer is in fact a custom implementation — it uses SunCalc to compute solar azimuth and elevation, then projects OSM building footprints and street-tree canopies into shadow polygons; this package was never actually used).
4. **Removed a dead environment variable**: `NEXT_PUBLIC_SHADEMAP_API_KEY` was previously passed from the map component into the solar shadow layer, but the layer never actually used it internally, making it an inert setting. It has been removed from the code, the documentation, and the environment configuration files (the identically named variable on Vercel can also be deleted).

## [v1.9.5] - 2026-07-02 - 🌊 - AESTHETICS - More Realistic Homepage Water Animation: Glints, Underwater Caustics, and Wave Motion
1. **Glints**: 22 small, horizontal flecks of light replace the original large oval glow, each flickering and stretching horizontally at its own rhythm to simulate the "broken silver" reflections of sunlight scattering across wave crests — the single most recognisable visual feature of real open water.
2. **Underwater caustics**: added two layers of light-mesh patterns generated with CSS `radial-gradient`, drifting diagonally at different speeds and in different directions and blended with `soft-light`, recreating the slow-moving texture of light and shadow underwater; the displacement is aligned to the pattern's period for a seamless loop.
3. **Upgraded waves**: the three wave layers now use irregular, multi-harmonic paths (for more natural undulation), with a white highlight outline along each crest, plus a `wave-bob` up-and-down animation layered on top — the combination of horizontal flow and vertical bobbing motion is closer to real water.
4. **Zero loading overhead**: all effects are implemented purely with CSS `transform`/`opacity` animations (GPU-composited, without triggering layout reflow) — no images, no external libraries, and no JavaScript animation loop — so homepage load time is unaffected; animations are also automatically disabled when `prefers-reduced-motion` is set.
5. **Fixed a hydration warning**: glint coordinates now use deterministic pseudo-random generation fixed to two decimal places, eliminating the hydration mismatch caused by floating-point serialisation differences between the server and the browser.
